# 前端任务：匹配页面 UX 分析与优化

## 任务描述

检查匹配相关页面的 UI/UX 设计，分析是否合理，并提出优化建议让用户更轻松地确认匹配。

## 需要分析的页面

1. **对账运行详情** `views/reconcile/RunDetail.vue` — 单次对账的匹配结果列表
2. **全局匹配列表** `views/reconcile/matches.vue` — 所有匹配结果管理
3. **手动匹配弹窗** `views/bill/components/ManualMatchModal.vue` — 手动匹配流程
4. **评分详情** `views/bill/components/ScoreDetail.vue` — 评分展示

## 分析维度

### 1. 信息展示
- 支付端和扣款端的关键信息（金额、商户、时间、银行卡）是否一目了然？
- 置信度展示是否直观？用户能否快速判断匹配质量？
- 评分详情是否易于理解？普通用户能否看懂？

### 2. 操作效率
- 批量确认/拒绝流程是否顺畅？
- 单个确认/拒绝是否需要太多点击？
- 是否支持键盘快捷键操作？

### 3. 筛选与排序
- 是否能按置信度排序？
- 是否能快速筛选出需要关注的 pending 匹配？
- 是否有"一键确认所有高置信度匹配"的功能？

### 4. 视觉对比
- 支付端和扣款端的对比是否清晰？
- 金额差异、时间差异是否有视觉高亮？
- 匹配/不匹配的字段是否有颜色区分？

## 优化方向

基于后端数据分析，97.7% 的匹配是自动确认的，只有 2.3% 需要人工审核。优化重点应该是：

1. **让用户快速处理少量 pending 匹配** — 而不是在大量 confirmed 中找 pending
2. **提供更直观的对比视图** — 左右对比支付端和扣款端
3. **一键操作** — 如"确认所有 ≥0.85 的匹配"
4. **评分可视化** — 用进度条或雷达图展示 5 维度评分

## 技术约束
- 使用 Vue 3 Composition API（setup script）
- TypeScript 严格类型
- 使用 Vben Admin / Ant Design Vue 组件库
- 保持现有 API 接口不变

## 输出要求
1. 分析当前页面的问题和不足
2. 提出具体的 UI/UX 优化建议（附代码示例）
3. 如果需要修改代码，直接修改对应文件
